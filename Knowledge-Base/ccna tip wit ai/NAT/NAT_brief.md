**Static **NAT의 핵심 개념은 무엇인가요? Static NAT는 **사설 **IP** 주소와 **공인 IP** 주소를 1:1로 고정적으로 **매핑하는 기술로, 외부에서 내부 서버로의 접속이 항상 동일한 공인 IP를 통해 가능하여 **외부 서비스 제공에 적합**합니다.
## 1. NAT(네트워크 주소 변환)의 기본 개념 및 필요성 
NAT는 IP 주소 고갈 문제 해결과 내부 네트워크 보호를 위해 사설 IP 주소를 공인 IP 주소로 변환하는 기술이다.


### 1.1. IP 주소 고갈 문제와 해결 노력 
IP 주소 고갈 문제는 인터넷의 급격한 성장으로 인해 발생했으며, 이를 해결하기 위한 다양한 기술들이 개발되었다.
1. **IP 버전 4 주소의 한계** 
  1. IP 버전 4 주소는 32비트 크기로, 약 2의 32승 개의 주소만 사용할 수 있다 .
  2. 인터넷 네트워크가 계속 성장하면서 IP 주소 고갈 문제가 발생했다 .
2. **IP 주소 고갈 문제 해결을 위한 초기 노력** 
  1. **서브네팅(Subnetting)**: 클래스 기반에서 큰 네트워크를 작은 네트워크로 나누는 기술이다 .
  1. 모든 네트워크에 동일한 서브넷 마스크(예: /24)를 적용하는 '고정 길이 서브넷 마스크(FLSM)' 방식은 여전히 IP 주소 낭비가 발생했다 .
  2. 예를 들어, 단말이 100대인 곳과 10대인 곳 모두에 /24를 주면, 256개까지 가능한 호스트 수에 비해 10대인 곳에서는 비효율적이다 .
  2. CIDR**(Classless Inter-Domain Routing)**: 클래스 개념을 깨고 '가변 길이 서브넷 마스크(VLSM)'를 사용하여 호스트 수에 따라 네트워크 프리픽스 길이를 가변적으로 할당하는 방식이다 .
  1. 이는 마치 피자를 사람 수에 따라 크기별로 나누는 것과 같다 .
  2. CIDR은 더 이상 클래스 기반이 아니며, 네트워크 프리픽스 길이를 임의로 조절할 수 있다 .
3. **IP 주소 할당 및 관리 효율화 기술** 
  1. DHCP**(**Dynamic** Host Configuration Protocol)**: IP 주소를 한 명에게 계속 주는 것이 아니라, 필요할 때만 할당하고 사용하지 않을 때는 회수하여 재활용하는 기술이다 .
  2. **사설 IP(Private IP)**: 기업 내부에서는 공인 IP 대신 사설 IP를 사용하여 공인 IP 사용량을 줄이는 방법이다 .
4. **궁극적인 해결책: IP 버전 6** 
  1. IP 버전 4의 32비트 체계에서 128비트 체계로 전환하여 IP 주소 고갈 문제를 근본적으로 해결한다 .
  2. IP 버전 6는 CCNA 토픽에 포함되어 있어 나중에 더 깊게 다룰 예정이다 .


### 1.2. 사설 IP 주소의 개념과 NAT의 등장 배경 
사설 IP 주소는 조직 내부에서 자유롭게 사용할 수 있는 IP 주소이며, 외부 통신을 위해 NAT 기술이 필요하다.
1. **사설 IP 주소의 특징** 
  1. 사설 IP 주소는 조직 내부에서 자유롭게 사용할 수 있는 IP 주소이다 .
  2. 공인 IP 주소와 달리 할당받을 필요 없이 임의의 대역을 누구나 사용할 수 있도록 허용된 주소이다 .
  3. **RFC 1918에 정의된 사설 IP 대역**은 반드시 기억해야 한다 .
  1. 10.0.0.0/8 대역: A 클래스 크기로, 회사에서 가장 많이 사용하며 대부분의 단말을 포함할 수 있다 .
  2. 172.16.0.0/12 대역: B 클래스 대역으로, 172.16.0.0부터 172.31.255.255까지 사용 가능하다 .
  3. 192.168.0.0/16 대역: C 클래스 대역으로, 192.168.0.0부터 192.168.255.255까지 사용 가능하다 .
  4. 이 대역들은 회사 내부에서만 사용되는 프라이빗 어드레스이므로, 내부 단말들은 공인 IP 없이 서로 통신할 수 있다 .
2. **사설 IP 주소의 한계와 NAT의 필요성** 
  1. **인터넷 통신 불가**: 사설 IP 주소는 인터넷 외부에서는 사용할 수 없다 .
  1. 여러 회사가 동일한 사설 IP 주소를 사용하기 때문에, 인터넷에서 이 주소를 사용하면 충돌이 발생한다 .
  2. 인터넷 라우터는 사설 IP 주소를 가진 패킷을 받으면 모두 폐기(드랍)해 버린다 .
  2. **공인 IP로의 변환 필요**: 외부(인터넷)와 통신하려면 내부의 사설 IP 주소를 공인 IP 주소로 변경하는 기술이 필요하다 .
  1. 이 역할을 하는 기술이 바로 **NAT(**Network Address Translation**)**이다 .


### 1.3. NAT의 작동 원리 및 역할 
NAT는 IP 헤더의 출발지 및 목적지 주소를 변경하여 사설 IP를 사용하는 내부 네트워크가 외부와 통신할 수 있도록 한다.
1. **NAT의 기본 작동 방식** 
  1. 내부 네트워크의 사설 IP(예: 10.1.1.1)는 인터넷으로 직접 나갈 수 없다 .
  2. NAT 장비(라우터)는 사설 IP 주소를 공인 IP 주소(예: 200.1.1.1)로 변환하여 인터넷으로 내보낸다 .
  1. 이때 출발지 주소(Source Address, SA)가 사설 IP에서 공인 IP로 변경된다 .
  3. 외부에서 응답 패킷이 돌아올 때는, NAT 장비가 공인 IP 주소를 다시 원래의 사설 IP 주소로 변환하여 내부 단말에 전달한다 .
  4. **네트워크 어드레스 트랜슬레이션(Network Address Translation)**은 네트워크 계층(3계층)의 IP 주소를 변환(트랜슬레이션)하는 기술이다 .
  1. 이는 사설 IP와 공인 IP를 매핑하여 연결해 주는 역할을 한다 .
2. **NAT의 주소 변경 범위: 출발지 및 **목적지 주소 
  1. NAT는 IP 헤더의 **출발지 주소**와 **목적지 주소**를 모두 변경하는 기술이다 .
  2. **나갈 때(내부에서 외부로)**: 내부 단말(예: 10.1.1.1)이 외부(예: 170.1.1.1)와 통신할 때, NAT 장비는 출발지 사설 IP를 공인 IP(예: 200.1.1.1)로 변환한다 .
  3. **들어올 때(외부에서 내부로)**: 외부 서버가 응답 패킷을 보낼 때, NAT 장비는 목적지 공인 IP(예: 200.1.1.1)를 원래의 사설 IP(예: 10.1.1.1)로 변환하여 내부 단말에 전달한다 .
  1. 즉, 나갈 때는 출발지 주소를, 들어올 때는 목적지 주소를 변경한다 .
3. IP 헤더** 변경의 일반적인 범위** 
  1. 일반적으로 NAT는 IP 헤더의 출발지 및 목적지 주소만 변경한다 .
  2. 하지만 고급 장비(예: 애플리케이션 레벨 방화벽)에서는 페이로드(실제 데이터)까지 분석하여 FTP, VoIP 트래픽 등을 식별하고, 때로는 데이터 일부를 변경하기도 한다 .


## 2. NAT의 종류: Source NAT와 Destination NAT, 그리고 매핑 방식 
NAT는 출발지 IP를 변경하는 Source NAT와 목적지 IP를 변경하는 Destination NAT로 나뉘며, 매핑 방식에 따라 Static, Dynamic, PAT로 구분된다.


### 2.1. Source NAT와 Destination NAT 
NAT는 패킷의 출발지 또는 목적지 IP 주소를 변경하는 시점에 따라 구분된다.
1. Source NAT: 출발지 IP 주소를 변경하는 기술이다 .
  1. 일반적으로 내부에서 외부로 나가는 통신에서 사설 IP를 공인 IP로 변경할 때 사용된다 .
  2. 첫 번째로 발생하는 패킷(응답 요청 패킷)의 출발지 주소가 변경되는 경우를 Source NAT라고 한다 .
2. **Destination NAT**: 목적지 IP 주소를 변경하는 기술이다 .
  1. 주로 외부에서 내부 서버로 접속할 때, 외부에서 접근하는 공인 IP를 내부 서버의 사설 IP로 변경할 때 사용된다 .


### 2.2. NAT의 매핑 방식: Static, Dynamic, PAT 
NAT는 사설 IP와 공인 IP를 어떻게 매핑하는지에 따라 세 가지 방식으로 나뉜다.
1. **Static **NAT** (정적 NAT)** 
  1. **1대1 **고정 매핑: 사설 IP 주소와 공인 IP 주소를 1대1로 고정적으로 매핑하는 방식이다 .
  1. 예를 들어, 10.1.1.1은 항상 100.1.1.1로, 10.1.1.2는 항상 100.1.1.2로 변환된다 .
  2. **장점**: 항상 동일한 공인 IP를 사용하므로 외부에서 내부 서버로의 접속이 용이하여 **외부 서비스 제공에 적합**하다 .
  3. **단점**: 공인 IP 주소 절약 효과가 없으며, 사설 IP 수만큼 공인 IP가 필요하다 .
2. **Dynamic NAT (동적 NAT)** 
  1. **1대1 **동적 매핑: 사설 IP 주소와 공인 IP 주소를 1대1로 매핑하지만, 어떤 사설 IP가 어떤 공인 IP와 매핑될지는 동적으로 결정된다 .
  1. 미리 정의된 공인 IP 풀(Pool)에서 사용 가능한 IP를 동적으로 할당한다 .
  2. 통신이 끝나면 할당된 공인 IP는 풀로 반납되어 다른 사설 IP가 사용할 수 있다 .
  3. 이는 DHCP와 유사하게 동적으로 IP를 할당하고 회수하는 방식이다 .
  2. **단점**: 공인 IP 풀의 개수보다 많은 내부 단말이 동시에 인터넷에 접속하려 하면, 매핑될 공인 IP가 없어 인터넷 통신이 불가능해진다 .
  1. 또한, 공인 IP가 고정되지 않으므로 외부에서 내부 서버로 접속하기 어렵다 .
3. **PAT (Port **Address Translation**) 또는 NAT **Overload 
  1. N대1** 매핑**: 여러 개의 사설 IP 주소를 **하나의 공인 IP 주소**와 매핑하는 방식이다 .
  1. **오버로드(Overload)**: 하나의 공인 IP 주소에 여러 내부 단말의 트래픽이 집중되므로 '과부하'라는 의미의 오버로드라고 불린다 .
  2. **포트 어드레스 트랜슬레이션(Port Address Translation)**: IP 주소뿐만 아니라 **포트 번호까지 변환**하여 여러 내부 단말을 구분한다 .
  1. 예를 들어, 10.1.1.1은 100.1.1.1의 11번 포트로, 10.1.1.2는 100.1.1.1의 12번 포트로 통신한다 .
  2. 외부에서 응답 패킷이 돌아올 때 포트 번호를 보고 원래의 내부 단말을 찾아 전달한다 .
  2. **장점**: 하나의 공인 IP로 약 6만 개(16비트 포트 번호: 65,536개)의 내부 단말이 통신할 수 있어 **IP 주소 절약 효과가 매우 크다** .
  3. **가장 많이 사용되는 NAT 방식**이다 .


### 2.3. NAT의 주요 장점 
NAT는 공인 IP 주소 절약과 내부망 보호라는 두 가지 주요 장점을 제공한다.
1. **공인 IP 주소 절약** 
  1. PAT 기술을 통해 하나의 공인 IP로 여러 내부 단말이 인터넷에 접속할 수 있어 공인 IP 주소 고갈 문제 해결에 기여한다 .
2. **내부망 보호 (IP 마스커레이딩)** 
  1. 내부 사설 IP 주소(예: 10.1.1.1)가 외부로 노출되지 않고 공인 IP 주소(예: 100.1.1.1)로 변환되어 나가기 때문에, 외부에서는 내부망의 원래 주소를 알 수 없다 .
  2. 이는 내부 네트워크의 IP 주소를 숨기는(마스커레이딩) 효과를 제공하여 보안을 강화한다 .
3. **부하 분산 (참고)** 
  1. L4 스위치 등에서 부하 분산 시에도 NAT 기술이 활용될 수 있으나, 본 강의에서는 자세히 다루지 않는다 .


## 3. Static NAT의 상세 이론 및 설정 
Static NAT는 1대1 고정 매핑 방식으로, 항상 정적인 변환 테이블을 유지하며, 외부 서비스 제공에 적합하다.


### 3.1. Static NAT의 특징 및 용어 
Static NAT는 고정적인 1대1 매핑을 특징으로 하며, 내부 및 외부 네트워크의 관점에 따라 주소 용어가 달라진다.
1. **Static NAT의 핵심 특징** 
  1. **1대1 **고정 매핑: 사설 IP 주소와 공인 IP 주소를 1대1로 고정적으로 매핑한다 .
  1. 예를 들어, 10.1.1.1은 항상 100.1.1.1로, 10.1.1.2는 항상 100.1.1.2로 변환된다 .
  2. **공인 IP 주소 절약 불가**: 사설 IP 수만큼 공인 IP가 필요하므로 공인 IP 주소 절약 효과는 없다 .
  3. **항상 존재하는 정적 테이블**: Static NAT를 설정하면 라우터에 변환 테이블이 항상 존재하며, 통신 여부와 관계없이 유지된다 .
  1. 이는 마치 단말에 고정 IP를 할당하는 것과 같다 .
2. NAT** 관련 용어: 인사이드(Inside)와 아웃사이드(Outside)** 
  1. **인사이드(Inside)**: NAT 장비(라우터)를 기준으로 내부 네트워크(사설 IP 대역)를 의미한다 .
  2. **아웃사이드(Outside)**: NAT 장비(라우터)를 기준으로 외부 네트워크(공인 IP 대역, 인터넷)를 의미한다 .
3. **NAT 관련 용어: 로컬(Local)과 글로벌(Global)** 
  1. **인사이드 로컬(Inside Local) 주소**: 내부 네트워크(인사이드)에 있는 호스트가 내부에서 서로를 바라볼 때 사용하는 사설 IP 주소이다 .
  1. 예를 들어, 10.1.1.1과 10.1.1.2는 서로를 10.1.1.1과 10.1.1.2로 인식한다 .
  2. **인사이드 글로벌(Inside Global) 주소**: 내부 네트워크(인사이드)에 있는 호스트를 외부 네트워크(아웃사이드, 글로벌)에서 바라볼 때 사용하는 공인 IP 주소이다 .
  1. 예를 들어, 외부에서는 10.1.1.1을 200.1.1.1로, 10.1.1.2를 200.1.1.2로 인식한다 .
  3. **아웃사이드 로컬(Outside Local) 주소**: 외부 네트워크(아웃사이드)에 있는 호스트가 내부에서 바라볼 때 사용하는 주소이다 .
  4. **아웃사이드 글로벌(Outside Global) 주소**: 외부 네트워크(아웃사이드)에 있는 호스트를 외부에서 바라볼 때 사용하는 주소이다 .
  1. CCNA에서는 아웃사이드 로컬과 아웃사이드 글로벌 주소가 항상 같다고 본다 .
  5. **정리**: '인사이드/아웃사이드'는 호스트의 위치를, '로컬/글로벌'은 바라보는 관점(내부/외부)을 나타낸다 .


### 3.2. Static NAT의 통신 과정 
Static NAT는 라우팅과 NAT 변환이 순차적으로 발생하며, 나가는 방향과 들어오는 방향에서 그 순서가 다르다.
1. Static NAT** 테이블 생성** 
  1. Static NAT 설정 시, 사설 IP와 공인 IP의 1대1 매핑 정보가 담긴 NAT 테이블이 라우터에 즉시 생성된다 .
2. **내부에서 외부로 나가는 통신 (인사이드 -> 아웃사이드)** 
  1. **라우팅 먼저**: 내부 단말(예: 192.168.0.167)이 외부(예: 8.8.8.8)로 통신을 시도하면, 라우터는 먼저 목적지(8.8.8.8)로의 **라우팅 경로를 확인**한다 .
  2. **NAT 변환**: 라우팅이 발생한 후, 라우터는 NAT 테이블을 확인하여 해당 출발지 주소(192.168.0.167)가 NAT 대상인지 확인한다 .
  1. NAT 대상이면, 출발지 사설 IP 주소를 매핑된 공인 IP 주소로 변환하여 패킷을 외부로 내보낸다 .
  3. **순서**: **라우팅 -> NAT 변환** .
3. **외부에서 내부로 들어오는 통신 (아웃사이드 -> 인사이드)** 
  1. **NAT 변환 먼저**: 외부에서 응답 패킷(목적지: 공인 IP 주소)이 라우터로 들어오면, 라우터는 먼저 NAT 테이블을 확인하여 해당 목적지 공인 IP 주소가 NAT 대상인지 확인한다 .
  2. **라우팅**: NAT 대상이면, 목적지 공인 IP 주소를 매핑된 사설 IP 주소로 변환한 후, 해당 사설 IP 주소로의 **라우팅 경로를 찾아 내부로 전달**한다 .
  3. **순서**: **NAT 변환 -> 라우팅** .
4. **중요성**: 이 라우팅-NAT 변환 순서를 정확히 이해하는 것은 고급 트러블슈팅에 매우 중요하다 .


### 3.3. Static NAT 설정 및 확인 명령어 
Static NAT는 간단한 명령어로 설정할 수 있으며, 다양한 명령어를 통해 변환 테이블과 통계 정보를 확인할 수 있다.
1. **Static NAT 설정 명령어** 
  1. IP 주소** 매핑**: ip nat inside source static [내부 로컬 IP 주소] [내부 글로벌 IP 주소] 
  1. 이 명령어로 사설 IP와 공인 IP를 1대1로 고정 매핑한다 .
  2. **인터페이스 지정**:
  1. interface [인터페이스 타입/번호]
  2. ip nat inside (내부 네트워크와 연결된 인터페이스) 
  3. ip nat outside (외부 네트워크와 연결된 인터페이스) 
2. **NAT 테이블 확인 명령어: **show ip nat translations 
  1. 이 명령어는 NAT 변환 테이블의 현재 상태를 보여준다 .
  2. **테이블 구성 요소**:
  1. **프로토콜(Protocol)**: TCP, UDP, ICMP 등 통신 프로토콜을 표시한다 .
  2. **인사이드 로컬(Inside Local)**: 내부 네트워크의 사설 IP 주소이다 .
  3. **인사이드 글로벌(Inside Global)**: 외부에서 바라보는 내부 호스트의 공인 IP 주소이다 .
  4. **아웃사이드 로컬(Outside Local)**: 외부 네트워크의 목적지 IP 주소이다 .
  5. **아웃사이드 글로벌(Outside Global)**: 외부 네트워크의 목적지 IP 주소이다 (CCNA에서는 아웃사이드 로컬과 동일) .
  3. **Static 엔트리**: 설정하자마자 항상 존재하는 고정 매핑 정보이다 .
  1. 프로토콜 필드는 비어 있으며, 타임아웃이 0으로 표시된다 .
  4. Dynamic** 엔트리**: 통신이 발생할 때 동적으로 생성되는 임시 매핑 정보이다 .
  1. **TCP/UDP 통신**: IP 주소와 함께 포트 번호가 표시된다 .
  2. **ICMP(Ping) 통신**: 포트 번호 대신 ICMP 아이디(식별자)가 표시된다 .
  3. 통신이 일정 시간(기본 24시간) 없으면 자동으로 삭제된다 .
3. **NAT 타임아웃 설정 명령어** 
  1. ip nat translation timeout [초] : 전체 NAT 엔트리의 기본 타임아웃 시간을 설정한다 (기본값 3600초) .
  2. ip nat translation tcp-timeout [초], ip nat translation udp-timeout [초], ip nat translation icmp-timeout [초] : 프로토콜별로 타임아웃 시간을 개별 설정할 수 있다 .
4. **NAT 테이블 삭제 명령어: **clear ip nat translations 
  1. 이 명령어는 동적으로 생성된 NAT 엔트리(Dynamic 엔트리)를 즉시 삭제한다 .
  2. 하지만 **Static 엔트리(고정 설정된 매핑)**는 삭제되지 않고 항상 남아 있다 .
5. **NAT 통계 정보 확인 명령어: **show ip nat statistics 
  1. Static 및 Dynamic 엔트리의 개수, 인사이드/아웃사이드 인터페이스 정보 등 NAT 관련 통계 정보를 보여준다 .


### 3.4. Static NAT의 활용: 외부 서비스 제공 
Static NAT는 고정적인 공인 IP를 제공하므로 외부에서 내부 서버로 접속해야 하는 서비스에 매우 적합하다.
1. **외부 접속 시도 가능**: Static NAT는 테이블이 항상 정적으로 존재하므로, 외부에서 항상 동일한 공인 IP 주소(인사이드 글로벌 주소)를 통해 내부 서버로 접속을 시도할 수 있다 .
  1. 외부에서 100.1.1.1로 접속하면, NAT 장비가 이를 10.1.1.1로 변환하여 내부 서버에 전달한다 .
2. **주요 활용 분야**: 웹 서버, 블로그 서버 등 **외부에 서비스를 제공해야 하는 장비**에 주로 사용된다 .
  1. 일반적인 클라이언트(내부 단말)가 인터넷에 나갈 때 1대1 Static NAT를 사용하면 공인 IP 낭비가 심하므로 잘 사용하지 않는다 .
3. **Dynamic NAT와의 차이점**: Dynamic NAT는 공인 IP 주소가 동적으로 변경되므로 외부에서 내부 서버로 접속하기에 적합하지 않다 .
  1. Static NAT는 공인 IP가 고정되어 있어 외부 서비스 제공에 유리하다 .
