VLAN과 트렁킹(Trunking)은 무엇이며, 실무에서 어떻게 활용해야 하는가? VLAN은 하나의 스위치를 여러 개의 독립적인 스위치처럼 가상화하여 물리적 인터페이스를 효율적으로 사용하고 브로드캐스트 도메인을 분리하는 기술이며, **트렁킹**은 여러 VLAN 트래픽을 하나의 물리적 링크로 전송하기 위해 802.1q 프로토콜을 사용하여 VLAN 태그를 추가하는 기술입니다. 특히, 트렁크 포트 설정 시 네이티브 VLAN을 명확히 정의하고 불필요한 VLAN 트래픽이 넘어오지 않도록 Allowed VLAN을 명시적으로 설정하는 것이 루핑 장애와 같은 네트워크 문제를 예방하는 데 매우 중요합니다.
## 1. VLAN의 개념과 동작 원리 
VLAN은 하나의 물리적인 스위치를 여러 개의 독립적인 가상 스위치처럼 나누어 사용하여 네트워크 효율성을 높이는 기술이다.


### 1.1. VLAN의 정의 및 필요성 
1. **VLAN은 네트워크 분할 기능이다** 
  1. VLAN은 네트워크의 효율성과 성능을 높이기 위해 등장한 개념이다 
  2. 스위치는 물리적으로 디바이스를 연결하는 역할을 하며, 포트라고 불리는 물리적인 인터페이스를 통해 연결된다 
  3. 예를 들어, 16포트 스위치에 5대의 PC만 연결된 네트워크가 두 개 있을 경우, VLAN을 사용하면 하나의 스위치로 두 개의 완전히 분리된 네트워크처럼 사용할 수 있다 
  4. 이는 10.10.10.0/24 네트워크와 10.10.11.0/24 네트워크를 하나의 스위치에서 각각 구성하는 것과 같다 


### 1.2. VLAN의 구성 및 동작 방식 
1. 포트** 단위로 VLAN을 설정한다** 
  1. 스위치의 각 포트에 VLAN 번호를 지정하여 가상 네트워크를 나눈다 
  2. 예를 들어, 특정 포트들을 VLAN 10번으로, 다른 포트들을 VLAN 20번으로 지정할 수 있다 
2. **VLAN별로 독립적인 MAC 주소 테이블을 관리한다** 
  1. VLAN으로 분리된 네트워크는 독립적으로 동작하며, 각 VLAN은 별도의 MAC 주소 테이블을 갖는다 
  2. 해당 VLAN에 연결된 프레임이 들어오면, 해당 MAC 테이블을 참조하여 프레임을 전달한다 
  3. 만약 MAC 테이블에 없는 프레임은 해당 VLAN 내에서만 플러딩(삭제)되며, 이는 독자적인 Layer 2 스위치처럼 동작하게 한다 
3. **물리적 인터페이스의 효율성 및 성능 향상** 
  1. VLAN은 물리적인 인터페이스를 효율적으로 사용할 수 있게 한다 
  2. 플러딩 범위가 한정되어 있어 네트워크 성능상 유리하다 
  3. 이러한 특성 때문에 스위치는 연결된 디바이스를 배선하는 역할에 가깝고, **스패닝 트리 프로토콜(STP)**과 같은 개념이 발생할 수밖에 없는 구조이다 
4. 브로드캐스트 도메인** 분리** 
  1. VLAN은 같은 브로드캐스트 도메인에서 발생하는 플러딩을 방지한다 
  2. 브로드캐스트 트래픽이 들어왔을 때도 같은 VLAN 내에서만 플러딩이 발생한다 
  3. 들어온 인터페이스를 제외한 나머지 인터페이스들이 같은 VLAN에 속한 네트워크와 통신할 수 있도록 처리한다 
5. **VLAN 확장 및 통신 환경 구성** 
  1. 스위치 포트들이 다른 스위치에 연결되어 있고, 같은 네트워크상에 있다면 VLAN이 동일하게 설정된 상태에서 연결이 가능하다 
  2. 네트워크에 장비가 추가되거나 용도에 따라 분리될 경우, VLAN을 구분하여 통신 환경을 구성한다 
  3. 이렇게 구성된 VLAN 간에 통신이 필요한 경우, 특정 구성을 통해 통신이 진행될 수 있다 


## 2. 트렁킹의 개념과 802.1Q 프로토콜 
트렁킹은 여러 VLAN의 트래픽을 하나의 물리적 링크로 전송하기 위해 802.1Q 프로토콜을 사용하여 VLAN 태그를 추가하는 기술이다.


### 2.1. 트렁킹의 필요성과 동작 원리 
1. **트렁킹의 필요성** 
  1. 스위치 포트를 VLAN 10번과 20번으로 나누어 사용하는 방법도 있지만, 이는 포트 낭비로 이어질 수 있다 
  2. 트래픽이 많지 않아 포트가 아까운 경우, **802.1Q **트렁킹을 이용하여 두 개 이상의 VLAN 트래픽을 하나의 물리적 링크로 함께 보낼 수 있다 
2. **트렁크 포트의 정의** 
  1. 트렁킹을 사용하는 포트는 특정 VLAN에 속하는 것이 아니라, **트렁크 포트**로 정의된다 
  2. 양쪽 스위치의 트렁크 포트를 연결하여 VLAN 10번과 VLAN 20번 트래픽이 하나의 링크를 통해 통신할 수 있도록 한다 
3. **VLAN 태그의 역할** 
  1. 트렁크 구간에서는 어떤 VLAN으로 정보를 보내야 할지 판단하기 위해 **VLAN ID가 포함된 형태, 즉 **VLAN 태그가 필요하다 
  2. VLAN 태그가 있어야만 트렁크 구간에서 프레임이 올바르게 인식되고 처리될 수 있다 
  3. 프레임이 VLAN 태그를 달고 나가면, 받는 쪽 트렁크 포트가 VLAN ID를 인지하여 해당 VLAN으로 전달한다 
  4. 따라서 VLAN 트렁킹 구간에서는 VLAN 태그가 필수적으로 이해되어야 한다 


### 2.2. 트렁킹 프로토콜: 802.1Q 
1. **트렁크 포트의 유형** 
  1. 스위치의 포트는 특정 VLAN에 속하거나 트렁크 포트가 될 수 있다 
  2. 트렁크 포트는 이더넷 인터페이스가 되어 다른 트렁크 포트와 연결되는 구조이다 
  3. 다른 스위치뿐만 아니라 L2 기능을 제공하는 서버의 인터페이스와도 연결될 수 있다 
  4. 두 개 이상의 스위치가 여러 브랜치로 설정되었을 때, 하나의 포트와 링크를 이용하여 여러 VLAN 트래픽을 보낼 수 있다 
2. **802.1Q 표준 프로토콜** 
  1. 트렁킹 프로토콜은 트렁크를 통해 VLAN 트래픽을 전송하는 방식을 정의한다 
  2. 현재 가장 널리 사용되는 표준 프로토콜은 **802.1Q**이다 
  3. 과거 시스코(Cisco)는 ISL이라는 자체 프로토콜을 사용했지만, 지금은 대부분 802.1Q를 사용한다 
3. **802.1Q 프로토콜의 특징: **네이티브 VLAN 
  1. 802.1Q 프로토콜은 태깅을 효율적으로 사용할 수 있는 방법을 제공한다 
  2. 여러 VLAN이 있을 때, 태그가 없는 정보는 기본 VLAN으로 인지하여 두 스위치 간에 합의할 수 있게 한다 
  3. VLAN 20번 트래픽이 전달될 때는 20번 태그를 붙인다 
  4. 태그가 없는 트래픽은 하나의 기본 VLAN, 즉 **네이티브 VLAN**으로 처리하는 프로토콜이다 
  5. 따라서 인터페이스를 트렁크로 설정할 때는 이러한 태깅 방식과 네이티브 VLAN의 개념을 고려하여 설정해야 한다 


### 2.3. 트렁크 포트 설정 시 고려사항 
1. **네이티브 **VLAN** 설정** 
  1. 802.1Q 트렁크 프로토콜을 사용하겠다고 명시한 후, 네이티브 VLAN을 설정한다 
  2. 예를 들어, 네이티브 VLAN을 10번이나 20번으로 설정할 수 있다 
2. Allowed VLAN** 설정** 
  1. 트렁크에 특정 VLAN(예: 10번)만 지나다니게 하고 싶다면, **Allowed VLAN**을 양쪽에 명시적으로 정의해야 한다 
  2. 이는 불필요한 트래픽을 방지하고, 대규모 데이터 센터나 캠퍼스 네트워크에서 특정 VLAN을 특정 목적이나 부서만 사용하게 해야 하는 경우에 중요하다 
  3. 명확하게 VLAN을 정의해 줄 필요가 있다 
3. **트렁크 포트의 활용 및 운영 명확화** 
  1. 트렁크 포트는 스위치의 백플레인에서 여러 포트를 하나의 채널로 묶어 사용하는 것과 유사하며, 트래픽 증가에 대비하여 활용될 수 있다 
  2. VLAN별로 트렁크 포트를 인라인으로 레이블링하거나 자동으로 지정하는 방법도 802.1Q 프로토콜을 통해 가능하다 
  3. 운영의 명확성을 위해 같은 벤더 장비라도 해당 포트가 트렁크 포트인지, 또는 특정 VLAN만 사용하는지 명시적으로 설정하는 것이 좋다 
  4. 이는 향후 운영상의 이슈를 방지하고, 모드를 명확히 인지하게끔 하는 데 도움이 된다 


## 3. 네이티브 VLAN 설정의 중요성과 루핑 장애 예방 
네이티브 VLAN을 명확히 설정하고 불필요한 VLAN 트래픽을 제한하는 것은 루핑 장애와 같은 네트워크 문제를 예방하는 데 매우 중요하다.


### 3.1. 네이티브 VLAN 미설정 시 문제점 
1. **루핑 장애 발생 가능성** 
  1. 네이티브 VLAN 설정이 명확하지 않으면, 뒤에 설명할 루핑 장애가 발생할 수 있다 
  2. 루핑 장애는 네트워크에서 가장 큰 장애 요인 중 하나로, 모든 디바이스의 통신에 영향을 미친다 
  3. CPU를 과도하게 점유하여 연결된 모든 포트의 통신이 불가능해지며, 서버나 PC 등 연결된 디바이스들도 과다 트래픽으로 인해 큰 장애 임팩트를 받을 수 있다 
2. **VLAN 1번의 특성 및 위험성** 
  1. 스위치에서 VLAN 1번은 기본(디폴트) VLAN으로, 삭제가 불가능하다 
  2. 아무런 설정 없이 같은 디바이스를 연결하면, 통신이 서로 되면서 같은 VLAN 1번으로 인지하게 된다 
  3. 트렁크 포트에서 네이티브 VLAN을 명시하지 않으면, VLAN 1번이 네이티브 포트로 통신하게 된다 
  4. 이는 태그 없는 프레임 헤더가 붙지 않은 트래픽이 들어오면 모두 VLAN 1번으로 인지되어 처리된다는 의미이다 
  5. VLAN 1번 포트는 삭제도 불가능하며, 디폴트로 지정된 모든 포트는 VLAN 1번으로 인지된다 


### 3.2. 외부 네트워크 연결 시 루핑 장애 확산 위험 
1. **관리 영역 외 루핑 장애의 영향** 
  1. 직접 운영하지 않는 영역(예: 고객사 또는 다른 사업자 영역)에서 루핑 장애가 발생할 수 있다 
  2. 이 경우, VLAN 1번 포트를 사용하지 않더라도, 연결된 몇 개의 포트를 통해 루핑 트래픽이 전달되어 영향을 받을 수 있다 
  3. VLAN 1번 포트가 활성화된 상태에서 트래픽이 1번 포트로 들어오면, 해당 포트를 통해 트래픽이 확장되거나 확산될 수 있다 
2. **의도치 않은 트래픽 유입** 
  1. 트렁크를 설정하고 아무 생각 없이 네트워크를 사용하다 보면, 의도치 않게 VLAN 1번 포트로 트래픽이 넘어올 수 있다 
  2. 이렇게 그룹화된 트래픽은 관리하고 있는 스위치 네트워크에 영향을 줄 수 있다 
  3. 스위치가 1번 포트를 사용하지 않더라도 이러한 문제가 발생할 수 있다 


### 3.3. 트렁크 포트 설정 권고 사항 
1. VLAN** 1번 사용 지양 및 명확한 설정** 
  1. 트렁크 설정 후에는 설정을 명확히 확인해야 한다 
  2. VLAN 1번은 사용하지 않는 것이 일반적인 권고 사항이므로, 기본적으로 VLAN 10번, 20번 등 실제 서비스하는 VLAN을 사용해야 한다 
  3. 다른 디바이스나 고객사 장비, 사업자 장비를 트렁크에 연결할 때 네이티브 VLAN을 설정하지 않으면, 트래픽이 VLAN 1번으로 넘어와 영향을 받을 수 있다 
2. **명시적인 VLAN 통신 설정** 
  1. 트렁크를 설정할 때는 단순히 연결만 중요시할 것이 아니라, 어떤 VLAN을 명시적으로 통신시킬지 명확히 인지해야 한다 
  2. VLAN 태그가 있는 경우에도 이를 이해할 수 있도록 설정해야 한다 
  3. VLAN 1번은 무조건 라우팅되도록 설정하고, 네이티브 VLAN인 경우 VLAN 1번을 제외한 나머지 VLAN으로 명시되어 들어오더라도, 태그된 프레임이 들어와도 이 디바이스가 없는 VLAN으로 인지하게끔 설계해야 한다 
  4. 따라서 네이티브 VLAN은 아예 없는 VLAN으로 설정하여, 실제 액세스할 때는 사용하지 않는 VLAN을 설정하는 것이 중요하다 
  5. 이는 태그 없는 프레임이 들어오더라도 받는 디바이스가 실제 VLAN으로 인식하지 못하게 하여 트래픽 전달이 되지 않도록 하는 것을 포함한다 
3. **VLAN과 트렁킹의 중요성** 
  1. VLAN과 트렁킹은 Layer 2 스위치의 기본적이지만 매우 중요한 설정이다 
  2. 잘 알고 있다고 생각할 수 있지만, 놓치기 쉬운 영역이므로 주의 깊게 설정해야 한다
