# 네트워크 트러블슈팅 사례 정리

## 사례 1. VMware NIC 이중화 구성에 따른 지연 및 패킷 손실

### 1. 장애 현상

- 정상적으로 동작하던 네트워크에서 특정 시점부터 지연 현상이 발생함.
- 대상 구간에 ICMP Ping을 500회 전송했을 때 패킷 손실률이 30% 이상 발생함.
- 간헐적인 지연과 패킷 손실로 인해 네트워크 루프 가능성을 의심함.

### 2. 원인 분석

- 스위치의 ARP 및 MAC 주소 학습 상태를 확인함.
- VMware 가상머신 4대와 연결된 경로에서 예상과 다른 방향으로 주소 학습이 이루어지는 현상을 확인함.
- VMware NIC 이중화 설정이 Active-Standby가 아닌 Active-Active로 구성되어 있었음.
- 해당 구성과 주소 학습 경로 이상을 바탕으로 루프 또는 비정상적인 L2 경로 형성 가능성을 의심함.

> 참고: ARP 테이블은 IP 주소와 MAC 주소의 매핑을 나타내며, 스위치의 MAC 주소 테이블은 MAC 주소가 학습된 포트를 나타냅니다. 실제 루프 여부는 MAC 주소 이동 로그, 브로드캐스트 증가, STP 상태 등 추가 증거로 확인하는 것이 좋습니다.

### 3. 조치 사항

- VMware NIC 이중화 정책을 Active-Active에서 Active-Standby로 변경함.
- 변경 후 스위치의 주소 학습 상태를 재확인함.
- 동일 대상에 ICMP Ping을 전송하여 통신 상태를 점검함.

### 4. 조치 결과

- 주소 학습이 정상 경로로 이루어지는 것을 확인함.
- 장애 발생 당시 관찰되던 지연 및 패킷 손실 증상이 해소됨.

### 5. 핵심 정리

VMware NIC 이중화 방식과 스위치의 주소 학습 경로가 연관된 장애 사례임. Active-Standby로 변경한 뒤 정상화되었으며, 유사 장애 발생 시 NIC 팀 구성, MAC 주소 이동 여부, STP 상태 및 브로드캐스트 트래픽을 함께 확인할 필요가 있음.

## 사례 2. 파이오링크 포트 바운더리 활성화 시 발생하는 통신 장애

### 1. 장애 현상

- 파이오링크 장비의 포트 바운더리(Port Boundary) 기능을 활성화하면 항상 발생하는 것은 아니지만 간헐적으로 지연 또는 통신 장애가 발생함.
- 장애 시 L3 구간에서 L4 구간을 거쳐 백본 방향으로 Ping이 정상적으로 도달하지 않음.
- 포트 바운더리 기능을 비활성화하면 통신이 다시 정상화되는 현상이 관찰됨.

### 2. 원인 분석

- 포트 바운더리 기능 활성화 여부에 따라 ARP 학습 결과가 달라지는 것을 확인함.
- 기능 활성화 시에는 백본 방향에서 해당 IP에 대한 ARP 정보가 학습되는 현상이 관찰됨.
- 기능 비활성화 시에는 파이오링크 다운링크 방향에서 ARP 정보가 학습되는 현상이 관찰됨.
- 추가 확인 결과, 동일 IP 주소를 사용하는 장비가 존재하는 IP 중복 문제가 확인됨.

### 3. 조치 사항

- 중복 사용 중인 IP 주소를 확인하고 IP 중복 문제를 제거함.
- IP 주소 정리 후 포트 바운더리 기능을 활성화한 상태에서 통신을 재검증함.
- ARP 테이블과 실제 통신 경로가 정상인지 확인함.

### 4. 조치 결과

- IP 중복을 제거한 후 기존 통신 장애 증상이 해소됨.
- 포트 바운더리 기능의 활성화 여부에 따라 발생하던 비정상적인 ARP 학습 현상이 더 이상 장애로 이어지지 않음을 확인함.

### 5. 핵심 정리

동일 IP 주소가 중복 사용되어 ARP 응답 또는 주소 학습 경로가 예상과 다르게 형성된 사례임. 포트 바운더리 기능은 장애 발생 조건과 연관되어 있었지만, 확인된 직접적인 문제는 IP 중복이었음. 유사 장애 시 IP 중복 여부, ARP 응답 주체, ARP 테이블 변경 및 실제 패킷 경로를 함께 확인할 필요가 있음.

## 공통 점검 항목

1. 장애 전후 ARP 테이블의 IP-MAC 매핑 비교
2. 스위치 MAC 주소 테이블의 학습 포트 및 MAC 이동 여부 확인
3. IP 중복 사용 여부 확인
4. VMware NIC 팀 구성 및 Active-Active/Active-Standby 정책 확인
5. STP 상태, 루프 감지 로그 및 브로드캐스트 트래픽 확인
6. 장애 구간별 Ping 및 패킷 손실률 비교
7. 설정 변경 전후의 구성과 점검 결과 기록
